## Overview

Sprint 119 closed the graph-presentation arc (ADR-086) but its post-deploy validation surfaced
BUG-030: the Ebbinghaus-decay trust score (S90) is fractional, while the
`auth.social_distances.path_trust_score` cache column is INTEGER — so a forced recompute can 500
`GET /paths/:targetUserId`, and because the batch route's cache INSERT sits inside the per-target
loop with no per-target catch, one bad pair can 500 the whole `/paths/batch` call that feed
ranking uses. PR A fixes the column to match the S90 semantics (DOUBLE PRECISION — maintainer
decision, this session), isolates per-target failures in the batch loop, and folds in the six
minor presentation-polish findings from the PR #150 review plus the S119 close-out bookkeeping.

PR B is the long-flagged root-cause fix for seed-path drift: regenerate
`infrastructure/postgres/init.sql` from a fully-migrated schema so there is ONE seed path
everywhere (local docker-compose, CI, any new env). Today init.sql is a drifted fresh-install
snapshot and CI papers over the gap with `scripts/ci-apply-full-schema.sh` (PR #143), a
self-described CI-only convergence workaround. After PR B, that script's role inverts: from
"converge the drifted seed" to "drift guard that proves init.sql stays converged". Recorded as
ADR-087.

PR C is the deferred desktop/mobile **five-second-test UX pass** — research-first per the standing
rule: audit every primary surface at desktop and 375px asking "can a newcomer tell what this page
is and what to do within five seconds?", compare against reference community products, present
ranked findings to the maintainer, and implement only the fixes the maintainer selects.

### Core Principle: Fix the source, not the symptom

Every item this sprint replaces a workaround or a lossy compromise with the truthful upstream fix:
the column adopts the score's real type (not rounding at write sites), the seed file adopts the
migrated schema (not another CI shim), and UX changes are chosen from observed audit evidence
(not guessed).

## New Concepts

- **One seed path (ADR-087)**: `init.sql` is the generated product of the migration chain, not a
  hand-maintained parallel snapshot. It is regenerated by script from a scratch DB that has had
  init.sql + `scripts/apply-migrations.sh` run to completion, and it seeds
  `public.schema_migrations` so a fresh install never replays the chain.
- **Drift guard**: `scripts/ci-apply-full-schema.sh` is KEPT after regeneration. On a converged
  init.sql it should apply zero genuinely-new statements; any genuinely-new statement means drift
  has reappeared and the job fails. Its sentinels become assertions on init.sql itself.
- **Five-second test**: per-surface audit question — within five seconds, can a newcomer answer
  "what is this page?", "what can I do here?", "what should I do next?" at desktop AND 375px.

## Critical Implementation Notes

1. **BUG-030 fix shape is decided: DOUBLE PRECISION migration** (maintainer, this session), NOT
   rounding at write sites. Three raw write sites exist and stay unrounded:
   `services/social-graph-service/src/routes/paths.ts:189` (single), `paths.ts:361` (batch),
   `services/pathComputation.ts:525` (precompute). After migration, grep consumers of
   `path_trust_score` for integer-formatting assumptions (display rounding is a presentation
   choice, fine; type assumptions are not).
2. **Batch isolation**: wrap the per-target compute+INSERT in try/catch INSIDE the loop; a failed
   target must degrade to the existing "no connection" per-target shape (never invent a new error
   shape mid-loop), log with target id. TDD: one target throws → response still 200 with the
   other targets present.
3. **New migration + CI**: date-named `20260716-path-trust-score-double-precision.sql`; run the
   `migration-validator` agent on it before commit; add a sentinel to
   `scripts/ci-apply-full-schema.sh` asserting the column type; demo receives it via
   `apply-migrations.sh` on deploy (NEW file — tracked-migration edits never reach demo, so never
   edit 009).
4. **Do not disturb shipped graph contracts while polishing**: ring rotation-only/anchor,
   decayTier opacity bands, `new > caller > focused` stroke precedence, fail-closed
   `active_recently`, truthful legend colors (emerald-500/green-400) are pinned S115/S118/S119
   contracts — polish items 1–6 must not move them; run the promoted Sprint 118/119 regression
   suites directly after touching `graphVisualEncoding.ts`.
5. **One 30-day window constant** (ADR-082/S118): the `isActiveRecently` alias must delegate to
   `isFormedRecently`'s implementation and constant — no second window.
6. **init.sql regeneration needs a real postgres and Docker is unavailable locally**: run the
   regen via a manual-dispatch GitHub Actions workflow that boots postgres, applies current
   init.sql + the full chain (reusing `ci-apply-full-schema.sh` semantics), `pg_dump
   --schema-only`, post-processes, and uploads the regenerated init.sql as an artifact to commit.
   Do NOT dump the demo DB — demo lacks PR #143's `uq_*_global` guard indexes (tracked-migration
   edits never reached it), so it is not a valid schema source.
7. **Regenerated init.sql MUST seed `public.schema_migrations`** with a row per migration file at
   regen time — otherwise a fresh install replays the whole chain onto an already-complete schema
   (the exact collision mess ci-apply-full-schema.sh exists to manage). This is the load-bearing
   detail of ADR-087.
8. **Preserve the curated seed data**: `pg_dump --schema-only` drops init.sql's hand-written seed
   rows/comments; the regen script must splice the curated seed section back in (clearly fenced
   generated vs curated sections). Reconcile RLS policies, ownership/GRANTs (roles must exist in
   a fresh container), extensions, and schema creation order.
9. **Acceptance for PR B**: CI integration job green against the NEW init.sql, AND
   `ci-apply-full-schema.sh` applies zero genuinely-new statements over it (all existing
   sentinels pass straight from the seed). Keep the script as the drift guard.
10. **PR C is research-FIRST** (standing rule): no implementation before the audit doc exists and
