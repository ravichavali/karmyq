## Differential evidence: real zod 3.25.76 vs 4.6.5 on the real shared schemas

**Harness:** in the scratchpad, `npm i zod@3.25.76` and `npm i zod@4.6.5` go into separate directories (`--ignore-scripts`). `ts.transpileModule` compiles the 9 shared schema files to CommonJS, and a `Module._resolveFilename` hook points `zod` at one version per run. **Source: Appendix A.** It covers 96 `validateRequest` cases: a valid body per request type, then missing/wrong-type/short/emoji/bad-enum/null/extra fields per type, 7 datetime shapes, number coercion, `Infinity`, URL shapes and array bounds. Result: **17 verdict changes, 56 message/code-only changes, 23 identical; no issue *path* changed.** Every verdict change is zod 4 rejecting what zod 3 accepted.

| # | Change | Probe | 3.25.76 | 4.6.5 | Decision |
|---|---|---|---|---|---|
| P1 | `.uuid()` checks RFC version/variant nibbles | `11111111-1111-1111-1111-111111111111` | accept | reject | **Preserve** with `z.guid()` |
| P2 | Custom messages | `'Title must be at least 5 characters'`, `'Must be valid ISO datetime string'`, `'Invalid community ID'`, … | shown | shown | **Preserve** (already true; pinned) |
| P3 | `error.format()` tree shape and issue paths | every rejecting case | `{_errors, <key>: {_errors}}` | same | **Preserve** (already true; pinned) |
| I1 | String `.min/.max/.length` count **code points**, not UTF-16 units | title `😀😀😀` (`min(5)`); role_name `😀` (`min(2)`); address `😀😀` (`min(3)`) | accept | reject | **Intentional** |
| I2 | `.datetime()` requires seconds | `2026-10-01T10:00Z` on `departure_time`, `return_date`, `recurring.end_date` | accept | reject | **Intentional** |
| I3 | `z.number()` rejects ±`Infinity` | `budget_range.max: Infinity` (JSON `1e400` parses to `Infinity`); `lat: Infinity` becomes `invalid_type` instead of the custom range message | accept (range-checked only) | reject | **Intentional** |
| I4 | Default messages and codes | missing `title`: `"Required"` → `"Invalid input: expected string, received undefined"`; `invalid_enum_value` → `invalid_value`; `invalid_string` → `invalid_format`; `invalid_union_discriminator` → `invalid_union`; a missing enum key now reads `Invalid option: expected one of …` | old text | new text | **Intentional** |

**Why each "intentional" is safe (evidence, not assumption):**
- **I1.** Only strings containing astral characters (emoji and the like) near a bound are affected. "At least 5 characters" means characters to the person reading the error. Postgres `char_length`/`varchar(n)` also count code points, so zod 4 now agrees with the DB. The `.max` direction becomes *more* permissive only for astral-heavy text: `roles[].role_name max(50)` and `roles[].description max(200)`, both inside the JSONB `payload`, which has no DB length bound. The web wizard's own pre-check is `description.trim().length > 0` (`apps/frontend/src/components/RequestWizard.tsx:65`). It does not replicate `min(5)` or `min(10)`, so the server was already the only enforcer.
- **I2.** Every in-repo producer emits `Date#toISOString()`, which always includes seconds. Sources: `apps/frontend/src/components/requests/shared/DateTimePicker.tsx:33`; `apps/frontend/src/lib/requestParser.ts` (`combineDateTime` and `parseTimeToISO` both `return … .toISOString()`); `services/simulation-service/src/data/realistic-data.ts:226`. Mobile does not send these payload fields.
- **I3.** `Infinity` is not representable in JSON. zod 3 accepted it, and `JSON.stringify` then stored `null` in the payload. Rejecting it with a 400 is strictly better. The in-process parse sites (table above) receive DB `numeric` values and finite arithmetic (`disclosureAuth.ts:105-133`), so a non-finite value there would be a new bug. Under zod 4 it would surface as a 500 instead of a silent `null`. This is Review Focus 4.
- **I4.** Nothing matches on zod's default text or codes. `git grep` for `Required`, `Invalid enum value`, `invalid_enum_value`, `invalid_string`, `invalid_union_discriminator`, `Expected string, received`, `received nan`, `Invalid url` and `Invalid discriminator` across `apps`, `services`, `packages` and `tests` finds only unrelated UI copy (`ProfileTab.tsx:498`, `public.tsx:331,336`, `providers/[id].tsx:230`, `QuickCreate.tsx:63,76`) and one test comment (`requests.test.ts:246`). The visible effect is the **copy** of `POST /requests` 400 messages for fields without a custom message. That gets documented in `services/request-service/CONTEXT.md`.

**Confirmation owed:** the maintainer reviewed revision 1 and asked that preserved and intentional changes be identified explicitly. Revision 2 does that. If any "intentional" row should be preserved instead, the fix is per field (e.g. a `.refine((s) => s.length >= 5, msg)` for I1). The request-contract test flips that row's expectation.

Also checked (4.4.3 and 4.6.5), with **no difference** on our inputs: `.email()`, `.url()` (including `javascript:`, which **both** accept; pre-existing, out of scope), `z.coerce.number()` on `'3'`/`'abc'`/`''`/`null`, `.default()` output, `.strict()` extra-key rejection, `.omit().extend().strict()`. `ZodError.issues` exists and `.errors` is `undefined` (`validate.ts:38,86` read `issues || errors`). `ZodSchema` is a type-only alias of `ZodType` in zod 4 (`node_modules/zod/v4/classic/compat.d.ts:43`).
