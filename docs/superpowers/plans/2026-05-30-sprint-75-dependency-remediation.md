# Dependency Vulnerability Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Clear all 25 open Dependabot alerts (16 high, 8 moderate, 1 low) to zero, then wire a blocking `npm audit --audit-level=high` gate into CI, codified as ADR-059 with an SLA.

**Architecture:** Patch transitive vulnerabilities at the leaf via root-`package.json` `overrides` (avoiding breaking framework downgrades), bump the one direct dep (`axios`), regenerate the single root lockfile, verify builds + runtime + zero-audit, then convert the existing critical-only CI audit step into a blocking high-level gate.

**Tech Stack:** Node.js/Express/TypeScript, Next.js 14, PostgreSQL 15, Bull queue, npm workspaces (single root lockfile).

## ⚠️ Critical Implementation Notes (read before Task 2)

1. **`uuid@11` is the riskiest override.** `bull@4.11.5` + `node-cron@3.0.3` resolve `uuid@8`. Forcing `uuid@>=11.1.1` globally MUST be verified at runtime: enqueue a Bull job (cleanup-service) and confirm a node-cron schedule fires. uuid v11 keeps CJS named exports so it *should* work — but prove it. Fallback: bump `node-cron`→`^4.2.1` + scoped bull override, documented.
2. **`postcss` MUST use `overrides`, never `npm audit fix --force`** (`--force` installs `next@9.3.3` — catastrophic downgrade). `overrides: { "postcss": "^8.5.10" }` patches inside next + @expo/metro-config without touching next's major. Confirm `next build` passes for `apps/frontend` AND `apps/landing`.
3. **Overriding leaves auto-clears expo parents** — do NOT bump `expo` itself (SDK upgrade is out of scope).
4. **Change the EXISTING CI audit step, don't add a duplicate.** `ci.yml` `security:` job already runs `npm audit --package-lock-only --audit-level=critical`. Update that step's level + comment.
5. **Extend the existing `overrides` block** (`tar`, `minimatch`, `react`, `react-dom`) — don't replace it. The `tar` override exists already; regenerating the lockfile is what clears the 3 tar alerts.
6. **Single root lockfile, npm workspaces.** No separate `apps/mobile/package-lock.json`. All overrides in root `package.json`; one `npm install` regenerates everything. Commit `package-lock.json`.
7. **Verify at `moderate` too.** Target is zero across all 25. Run `npm audit --package-lock-only --audit-level=moderate` clean before raising the gate. Gate itself stays `high` per ADR SLA.
8. **`git push --no-verify`** is the emergency escape if the gate blocks a hotfix — document in ADR.
9. **`npm test` (unit + regression) MUST pass post-override** — it's the safety net for transitive incompatibilities. Treat any new failure as an override incompatibility.

## Task 2: Write the failing security test (TDD)

**Files:**
- Create: `tests/tdd/sprint-75-security-gate.test.ts`

- [ ] **Write the test FIRST** — it must fail now (gate is critical-only, alerts present) and pass at sprint end.

```ts
// tests/tdd/sprint-75-security-gate.test.ts
import { execSync } from 'child_process';
import { readFileSync } from 'fs';
import { join } from 'path';

const ROOT = join(__dirname, '..', '..');

describe('Sprint 75 — dependency security gate', () => {
  it('CI audit step blocks at high severity (not critical)', () => {
    const ci = readFileSync(join(ROOT, '.github/workflows/ci.yml'), 'utf8');
    expect(ci).toContain('--audit-level=high');
    expect(ci).not.toContain('--audit-level=critical');
  });

  it('root package.json pins axios to a patched version', () => {
    const pkg = JSON.parse(readFileSync(join(ROOT, 'package.json'), 'utf8'));
    const axios = pkg.dependencies.axios.replace(/[^\d.]/g, '');
    const [maj, min] = axios.split('.').map(Number);
    expect(maj > 1 || (maj === 1 && min >= 16)).toBe(true);
  });

  it('npm audit reports zero high/critical vulnerabilities', () => {
    const out = execSync('npm audit --package-lock-only --json', { cwd: ROOT }).toString();
    const { metadata } = JSON.parse(out);
    expect(metadata.vulnerabilities.high).toBe(0);
    expect(metadata.vulnerabilities.critical).toBe(0);
  });

  it('npm audit reports zero moderate/low vulnerabilities (sprint 75 target: all 25 → 0)', () => {
    const out = execSync('npm audit --package-lock-only --json', { cwd: ROOT }).toString();
    const { metadata } = JSON.parse(out);
    expect(metadata.vulnerabilities.moderate).toBe(0);
    expect(metadata.vulnerabilities.low).toBe(0);
  });
});
```

> `npm audit --json` exits non-zero when vulns exist; wrap in a try/catch capturing stdout if the test runner treats the throw as a hard error, or assert on the parsed `metadata` either way.

- [ ] **Verification** — `npm run test:tdd` shows these 4 assertions failing.
