Today — three divergent surfaces

  • BrowseFeed (dashboard) — curated/ranked, inline offer, on-duty filter
  • community/tabs/BrowseTab — dense rows + an admin console mixed in (586 lines)
  • Feed/Feed.tsx — rich polymorphic cards + stories, but unmounted/legacy

→ the open help request is rendered three ways, fed by three data paths, with three action vocabularies.

After — one model, two views

  • One canonical request card (trust shown, commitment legible, shared status token)
  • Action altitude: a decision band rises above browseable requests
  • activity/story as dismissible texture, never outranking a real ask
  • A finite, finishable queue with a "you're caught up" end-state — not infinite scroll
  • The community admin console is a distinct region, not the feed

These mockups embed no live data, tokens, or API calls — the only external resource is the Tailwind CDN script. They exist to be compared, then discarded once Sprint 85 implements the real components.
