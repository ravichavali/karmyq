================================================================================
                         THE ARCHITECTURE AT A GLANCE
================================================================================

KARMYQ USES LOOSELY COUPLED MICROSERVICES:

Frontend (React PWA)
        ↓
API Gateway (Nginx on port 3000)
        ↓
┌────────────────────────────────────────┐
│ 7 Independent Microservices:           │
│ • auth-service (users & login)         │
│ • community-service (communities)      │
│ • request-service (help requests)      │
│ • reputation-service (karma/trust)     │
│ • messaging-service (chat)             │
│ • notification-service (emails)        │
│ • governance-service (voting) [STUB]   │
└────────────────────────────────────────┘
        ↓
PostgreSQL + Redis (shared infrastructure)

WHY THIS DESIGN?
✓ Each contributor owns ONE service completely
✓ Services don't depend on each other's code
✓ Event-driven = no cascading failures
✓ Perfect for community development
✓ GitHub Copilot works great with this structure

                      7 MICROSERVICES EXPLAINED
================================================================================

1. AUTH-SERVICE (User accounts & authentication)
   - User registration, login
   - Session management
   - Password reset
   - JWT tokens

2. COMMUNITY-SERVICE (Communities & membership)

4. REPUTATION-SERVICE (Karma & trust scores)
   - Calculate karma (points for helping)

   - Reward good behavior
   - Improve request matching

5. MESSAGING-SERVICE (In-app messaging)
   - Direct messaging between users
   - Conversation threads
   - Real-time updates via WebSocket
   - Message history

6. NOTIFICATION-SERVICE (Emails & notifications)
   - Send emails
   - Send push notifications
   - Email templates
   - Notification preferences
   - Weekly digests

7. GOVERNANCE-SERVICE (Community governance) [STUBS]
   - Proposals & voting
   - Conflict resolution
   - Community norm setting
   - Decision-making processes
   (This service is intentionally stubbed to attract contributors!)

================================================================================
                         CORE CONCEPTS TO KNOW
================================================================================

LOOSELY COUPLED MICROSERVICES
- Each service is independent
- Services communicate via APIs and events
- No hard code dependencies

EVENT-DRIVEN ARCHITECTURE
- When something happens, an event is published to Redis queue
- Other services subscribe and react asynchronously
- Example: Request created → Reputation awards karma → Notification sends email
- All happen independently, in parallel

SHARED TYPES
- All services use the same TypeScript interfaces
- Ensures API contracts are consistent
- Frontend and backend speak the same language

DUNBAR'S NUMBER
- Communities capped at 150 members
- This is the limit of human trust relationships
- Key to Karmyq philosophy

PRESTIGE SYSTEM
- Instead of money, members earn KARMA
- Karma earned by helping others
- High karma = more prestige in community
- Motivates good behavior

================================================================================
                          TROUBLESHOOTING
================================================================================

"docker-compose: command not found"
→ Install Docker Desktop from https://www.docker.com/products/docker-desktop

"Port 3000 already in use"
→ Kill whatever is using it or change port in docker-compose.yml

"Cannot connect to database"
→ Wait 10 seconds, PostgreSQL takes time to start
→ Check logs: docker-compose logs postgres

"Service is crashing"
→ View logs: docker-compose logs <service-name>
→ Usually a missing environment variable or not-ready dependency
→ Restart: docker-compose restart <service-name>

"Code changes aren't showing up"
→ Services auto-reload, but if not:
→ docker-compose restart <service-name>

For more troubleshooting, see QUICK_START.md
